# HANTER - Owner Ed25519 Root Proof Gate

Original work: Alexander Nikolaevich Romaskevich (RomaskevicH), Founder, Owner, CEO and Chief Systems Architect of IMPERIAL Core.

Date: 2 November 2026. This is a working *offline cryptographic proof of possession* module, not a production Owner identity enrollment or NCA activation.

## Verified code

- Module: hanter_pilot/owner_root_proof.py
- Tests: tests/test_owner_root_proof.py
- CI: .github/workflows/owner-root-proof-gate.yml

The verifier requires a trusted Ed25519 public key injected separately from the untrusted request, verifies a five-minute signed challenge with purpose, tenant, key ID and nonce, and consumes that challenge atomically in local SQLite. Key substitution, changed purpose/tenant, stale challenge, replay and any production/external-effects claims are rejected.

The only signature supplied by this repository is one produced **inside tests** using temporary synthetic keys. There is no Owner private signing key here, no on-chain or commercial authority and no state transition that can authorize a real worker.

The returned receipt states OFFLINE_PINNED_KEY_POSSESSION_VERIFIED and explicitly sets externally_attested_owner_identity=false, real_ai_passport_issued=false and production_authorized=false. It establishes that the signer controls **the private key corresponding to a separately pinned public key**, nothing about the actual human identity of that signer.

## Enrollment procedure for a real Owner

1. On a separate Owner-controlled hardware device or trusted key manager, establish the genuine signing identity. The private Ed25519 key MUST NOT be uploaded to GitHub, Supabase, chat, developer workstation, CI or agent runners.
2. Independently pin the public-key fingerprint in a trusted, private system, with an audit and verified human-to-key binding. This repository intentionally does not implement that final enrollment ceremony.
3. The verification server generates a fresh challenge with the correct tenant and purpose. The Owner signs the domain-separated canonical bytes using their trusted signing device, and returns only the signature.
4. Verify the signature against the separately pinned public root and atomically consume its nonce. The resulting local proof does not grant execution, spending, or approval rights.
5. Independently deploy revocation, issuer separation, signed AI Passport, Guardian Core, Approval Gateway, sandboxed worker, ProofGraph/Audit Ledger external anchoring, and QA operated by a separate trust domain.
6. Keep the NCA in a guarded idle state until all these production trust boundaries are verified; do not convert self-declared booleans or a test key into authority.

## Reproduce

Install existing HANTER pinned cryptography dependency:

    python -m pip install -r hanter_pilot/requirements-pilot.txt
    python -m unittest discover -s tests -p 'test_owner_root_proof.py' -v

Only test keys are generated by the suite; no keys are generated for real Owner enrollment or worker activation.
